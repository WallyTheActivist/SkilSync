# Developer and Operations Manual

## Source Layout

| Path | Responsibility |
|---|---|
| `client/src/App.tsx` | Browser routes and client-side role-aware route guards. These guards are not a replacement for server authorization. |
| `client/src/contexts/AuthContext.tsx` | Current user state and session restoration via `/api/auth/me`. |
| `client/src/services/api.ts` | Axios API client; uses `/api` and sends browser credentials. |
| `server/src/index.ts` | Express middleware, router mounting, health endpoint, and error handling. |
| `server/src/routes/` | HTTP paths, role middleware, and route-level validators. |
| `server/src/controllers/` | Request handling, ownership/business checks, Prisma operations, and responses. |
| `server/src/services/matchingService.ts` | Match score, readiness, ranked matches, skill gaps, and rule-based recommendations. |
| `server/src/services/reportService.ts` | Admin report calculations and PDFKit exports. |
| `server/src/middleware/` | Auth/RBAC, origin/body checks, validation response, upload handling, and errors. |
| `server/src/config/database.ts` | Prisma client used by most server modules. |
| `server/prisma/schema.prisma` and `server/prisma/migrations/` | Database model and migration source. |

The report service currently constructs its own Prisma client instance; it uses the same environment-provided database URL.

## Request Lifecycle

1. Vite proxies browser `/api` requests to Express during local development.
2. Express applies Helmet/CSP, CORS with credentials, general and auth rate limits, request-origin validation, JSON/urlencoded body limits, and JSON-object inspection.
3. Route validators return 400 with field messages when constraints fail.
4. Protected routes verify the JWT and check the required role. Controllers enforce ownership for student/employer-owned resources.
5. Controllers/services access SQLite through Prisma and return JSON or PDF responses.
6. `notFound` and `errorHandler` produce generic failure responses without stack traces.

## Authentication and Security

- Password creation/reset uses bcryptjs with 12 rounds; login verifies through bcrypt compare.
- JWTs use HS256, expire after `JWT_EXPIRES_IN` (default `7d`), and require `JWT_SECRET`; production requires at least 32 characters.
- Browser session cookie name is `ss_token`, HttpOnly, SameSite Strict, scoped to `/api`, and Secure in production.
- Unsafe browser requests are checked against `CLIENT_URL`; cookie-authenticated writes require an origin/referrer. Bearer clients may omit browser origin headers.
- Student, employer, admin, and report access is enforced by server middleware; client routing is presentation only.
- Shared validators are in `server/src/middleware/validation.ts`; authentication has additional rules in `server/src/routes/auth.ts`.
- Prisma query APIs are used for current persistence. Do not concatenate user input into SQL.
- React escapes interpolated text. User-controlled link URLs are restricted to HTTP(S); image uploads verify JPEG/PNG/WebP signatures and are limited to 5 MB.
- Reset tokens are random and stored as SHA-256 hashes, but email delivery is absent. No raw reset token is returned.
- The login page does not display or prefill demo credentials. The explicit `npm run seed` command requires development mode, local SQLite, an opt-in flag, and unique per-account credentials in the ignored local `.env`; it does not print those credentials.

## Matching Behavior

- Required skill weight is `importance × 5` points. A student meeting the required proficiency receives all points; lower proficiency receives proportional points. Missing skills receive no points.
- Up to three skills not required by the internship add two points each, capped at six. The final score is capped at 100. A posting with no required skills currently receives a neutral score of 50.
- Match labels are derived from score thresholds in `matchingService.ts`.
- Readiness combines skill count (20%), average proficiency (30%), average match across up to 20 active internships (40%), and application history (10%).
- Skill-gap results distinguish missing from weak skills and rank the top gaps by frequency × gap size. Recommendations are rule-based; they are not generated by machine learning.

These values document the current implementation and may change with product requirements.

## Reporting Behavior and Limits

- Admin analytics API is `/api/admin/analytics`; the client Analytics page uses it.
- Admin report API and PDF export are under `/api/reports`.
- Application report `averageTimeToDecision` is currently the fixed placeholder `7` days.
- Skills demand/trend is calculated from current link counts, not historical measurements.
- Schema models `Notification`, `AuditLog`, `StudentReadinessMetric`, and `InternshipMatchMetric` are not wired to corresponding runtime workflows. No notification API or automatic audit writes exist.
- There is no client Reports route, email service, resume-upload route, PostgreSQL/Supabase configuration, or deployment infrastructure in this repository.

## Development and Test Commands

From `server/`:

```powershell

npm run build
npm test
npm run test:unit
npm run test:integration
npx prisma generate
npx prisma migrate deploy

```

From `client/`:

```powershell
npm run dev
npm run build
npm run lint
```

See [Testing Strategy](../TESTING_STRATEGY.md) for isolated test database setup and test layer boundaries. The default server test suite includes an opt-in SQLite database integration test; it is skipped unless a dedicated test URL is configured.

## Operational Cautions

- Keep `.env` files and production secrets out of source control.
- Never enable demo seeding against a shared/production database. The seed utility is intended only for a disposable local SQLite database and requires explicit local credentials.
- Back up the SQLite file and the `uploads/` directory together for a local deployment.
- Use HTTPS, managed secrets, protected persistent storage, backups, and a separately reviewed migration plan before any public deployment.
- The production database provider and email reset delivery are future work, not current capabilities.
